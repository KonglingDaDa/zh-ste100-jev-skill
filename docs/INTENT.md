# `zh-ste100-skill` 意图书（G0 + G1）

## 1. 一句话目的

把**中国民机维修简化中文硬门禁**（对标 ASD-STE100 与《民用飞机维修技术数据简化语言规范》/ GB/T 42852-2023）与**汉语言文学竹节句软处理**（余光中《论中文的常态与变态》《论的的不休》、现代汉语意合流水句）结合成一套专属于中文的开源 Agent 写作技能与双层检查器，彻底解决 AI 中文报告「每个字都认识、连起来不知所云、满篇打太极」的顽疾。

## 2. 已确认意图摘要（Confirmed Intent）

- **目标读者**：AI 编码 Agent（撰写任务汇报、操作步骤、报错说明、系统提示词、技术文档）与中文开发者 / 半甲方决策者。
- **核心架构（软硬双引擎）**：
  - **硬信息层（Hard Gates）**：结论确定性（首句死判断、已验/未验显式二分、禁太极含糊词）、文体三档句长上限（`procedure` ≤ 25 字 / `report` ≤ 35 字 / `descriptive` ≤ 40 字）、一句一动作、禁用分号与长连词串动作、禁用虚动词（文字义肢 `进行/作出/加以/予以/完成对…的`）、禁用互联网黑话、一物一词。
  - **软处理层（Soft Chinese Flow）**：拆解左分支多层「的」字长定语（防短期工作记忆过载）、剥离英文直译介词套壳（`基于…下 / 针对…问题 / 对于…而言`）、改用汉语**竹节句（流水句）**按「前提/原因 → 具体施事+真动词 → 结果状态」顺排、减少无施事被动句（`被 / 由…所`）。
  - **受控核心词典（Controlled Lexicon）**：提供 6 大技术与汇报领域的「批准真动词表」与「禁用/替换词典」。
  - **双层检查器**：零第三方依赖的 `scripts/zh-ste-lint.py`（确定性静态扫描硬违规与西化软病句）+ 可选 `scripts/zh-ste-jev.py`（调用 `typesafe/jev-latest` 对确定性、竹节通顺度与原意保真做语义复核）。

## 3. 明确不做清单（Non-Goals）

1. **不做中英文空格与全半角排版美化**：不替代 AutoCorrect 等排版工具；本仓只管词义、句法结构、语序与确定性。
2. **不改写文学、小说、品牌营销与修辞创意文案**：只面向读错有代价的 AI 任务汇报、技术操作、报错信息、Prompt 与说明文档。
3. **主检查器不引入任何第三方 Python 依赖**：`scripts/zh-ste-lint.py` 严格只用 Python 3 标准库，单文件即拷即用。

## 4. 可验证成功标准（Success Criteria）

1. `python3 scripts/zh-ste-lint.py --selftest` 全部内置断言 100% 通过，退出码为 `0`。
2. `python3 scripts/zh-ste-lint.py --mode report examples/after-only.md` 零硬违规通过（退出码 `0`）。
3. 对典型「AI 西化病句汇报」运行 `scripts/zh-ste-lint.py --mode report --json`，能准确检出虚动词（`nominalization`）、太极含糊词（`taichi-hedge`）、长定语堆叠（`de-stacking`）、介词套壳（`translationese-shell`）、悬空指代（`dangling-pronoun`）、黑话（`jargon-buzzword`）、分号串联（`semicolon-join`）与超长句（`long-sentence`）。
4. `python3 -m unittest discover -s tests -v` 全量契约测试与边界测试通过。
5. 本机 Pi 全局技能注册就绪，且 `lens_diagnostics` 检查全部代码与文档无阻断项。

## 5. 单向数据流与接缝契约（G1）

```text
[输入 Markdown/文本 + 运行档位 (report | procedure | descriptive)]
        │
        ▼
┌──────────────────────────────────────────────────────────┐
│ 1. Markdown 结构剥离器 (Markdown Segmenter)               │
│    跳过 fenced code / 行内代码，切分标题、列表、表格、正文句 │
└──────────────────────────────────────────────────────────┘
        │  产出: Segment[] (file, line, col, text, context)
        ▼
┌──────────────────────────────────────────────────────────┐
│ 2. 软硬双引擎静态检查器 (scripts/zh-ste-lint.py)          │
│    • 硬门禁 (advisory-free): 句长/分号/虚动词/黑话/太极词  │
│    • 软章法 (advisory): 多层"的"堆叠/介词壳/悬空指代/被字句 │
└──────────────────────────────────────────────────────────┘
        │  产出: LintReport (contracts/schema.py, zh-ste100/v1)
        ▼
┌──────────────────────────────────────────────────────────┐
│ 3. 可选 Jev 语义复核器 (scripts/zh-ste-jev.py)            │
│    • 结论是否给死 / 竹节句是否自然 / 改写是否保真          │
└──────────────────────────────────────────────────────────┘
        │  产出: JevSemanticVerdict (zh-ste100-jev/v1)
        ▼
[终端人类可读报告 / JSON 结构化输出 / 退出码门禁 (0 | 1 | 2)]
```

- **状态归属**：Linter 与 Jev 复核器均为**纯无状态函数式管线**，不落盘隐藏状态；同义轮换词频统计仅在单文件扫描生命周期内持有。

## 6. 假设日志（Assumptions）

| ID | 决策内容 | 理由 | 若错的代价与复核条件 |
|----|----------|------|----------------------|
| A1 | 中文句长按「有效汉字 + 英文单词数」计量（不计标点与行内代码），三档上限设为：`procedure` 25、`report` 35、`descriptive` 40 | 对标民机简化中文与上游 STE100（指令 20 词 / 说明 25 词），结合中文单字信息熵折算 | 若用户在特定长路径汇报中误报，可通过 `--max-chars` 或行内反引号包裹路径豁免 |
| A2 | 单句内连续出现 `≥ 3` 个「的」字判为 `de-stacking`（左分支长定语预警） | 余光中《论的的不休》与汉语阅读心理学表明，三层以上前置定语会显著挂起工作记忆 | 属于 `advisory` 提示级，不直接阻断 CI，提醒拆为竹节短句 |
| A3 | 「确定性」区分为两类：`report` 档禁止主观测度太极词（`应该/大概/基本上/似乎/理论上/一定程度上`），但保留客观故障排查中的真实情态词（`可能` 需配已验证边界） | 兼顾用户对「任务汇报给死结论」的硬诉求与故障分析中「不把可能原因谎报为确定原因」的事实保真 | 在 `--mode report` 下对太极词按硬违规拦截；在 `descriptive` 下保留客观情态 |
