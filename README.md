# `zh-ste100-jev-skill` — 中文受控技术与汇报写作技能（`篇法 · 句法 · 字法` 三层九律）

> **核心宗旨：高确定性、真动词、竹节短句、一眼看懂。**
> - **第一层【篇法】管确定性**：首句直接给死结论，查实再报，禁打太极、禁免责叠甲（静态门禁 + `Jev` 百毫秒语义终审）
> - **第二层【句法】管语序顺畅**：余光中《论中文的常态与变态》+ 现代汉语「竹节流水句」，砍掉连串「的」字长定语与西化介词壳
> - **第三层【字法】管选词精准**：中国民机《简化语言规范》+ ASD-STE100 受控词表，真动词立骨、真数字点名

---

## 为什么做这个项目？

英文 **ASD-STE100（简化技术英语）** 是为了让飞机维修工不可能读错指令而设计的受控语言。但中文 AI 任务报告和技术文档之所以让人觉得**「每个字都认识，串在一起却不知道在说什么，而且满篇打太极」**，病根同时出在**篇、句、字**三层：

1. **篇法病（打太极与免责叠甲）**：不把问题查到底，满嘴 `应该已经、基本上、大概、目前还不能确定是 A 还是 B、相关测试通过但还需观察`，读完还是不知道到底成了没。
2. **句法病（左分支「的的不休」与西化介词壳）**：英文从句在名词后（右分支），中文修饰语在名词前（左分支）。AI 动辄写 `在…配置下，针对…在…情况下引发的…问题`，读者读了 40 个字还没见到核心动词，短期工作记忆直接挂死；遇到简单概念（如「防抖就是连点十次，只认最后一次」），也非要套壳改写成温吞啰嗦的西化说明书。
3. **字法病（弱动词义肢与黑话伪术语）**：余光中先生在《论中文的常态与变态》中痛批的西化病——把鲜活的真动词冻成抽象名词，再用 `对…进行 / 作出 / 完成对…的` 拼凑；或者堆砌 `赋能、闭环、收口、具备良好的可用性` 等空洞伪术语。

本项目按中国传统文章学的**「篇法 · 句法 · 字法」三层九律**自上而下治理，一层只管一件事，绝不搞拼盘大杂烩：

```text
┌───────────────────────────────────────────────────────────────────────────┐
│ 第一层：篇法（确定性铁律） ← 民机报告纪律 + Jev（System One）语义终审      │
│   • 第 1 律 taichi-hedge     : 结论给死，禁“基本上/应该已经/大概/似乎”     │
│   • 第 2 律 empty-overclaim  : 开门见山，禁套话铺垫、虚夸与免责叠甲尾巴   │
├───────────────────────────────────────────────────────────────────────────┤
│ 第二层：句法（竹节与语序） ← 余光中《论中文的常态与变态》+ 汉语竹节流水句  │
│   • 第 3 律 bamboo-length    : 竹节断句，一事一顿（25/35/40字），禁分号串联│
│   • 第 4 律 de-stacking      : 单句“的”≤2 个，以动宾小句做主语而非“X的Y”   │
│   • 第 5 律 western-shell    : 剥除“基于…下/在这种…下/针对…问题”欧化套壳  │
├───────────────────────────────────────────────────────────────────────────┤
│ 第三层：字法（选词与定名） ← 中国民机《简化语言规范》+ ASD-STE100 词表     │
│   • 第 6 律 weak-verb        : 22 个真动词立骨，砍掉“对…进行/作出/完成”    │
│   • 第 7 律 buzzword-abstract: 禁黑话与“具备…性/实现了…化”伪抽象度词       │
│   • 第 8 律 vague-reference  : 点真名与准确数字，禁“该/其/此/相关/若干”    │
│   • 第 9 律 synonym-rotation : 同篇一义一词，禁止近义词轮换               │
└───────────────────────────────────────────────────────────────────────────┘
```

## 三层九律详解与正反例对照

### 第一层：篇法（确定性铁律 —— 一锤定音，拒绝太极与叠甲）

| 律号与规则 ID | 管什么 | ❌ 病句（太极推诿 / 套话 / 免责叠甲） | ✅ 受控改写（死结论 + 明确边界） |
| :--- | :--- | :--- | :--- |
| **第 1 律 `taichi-hedge`** | 首句给死判断；查实再报，禁推诿词 | `日志显示超时，目前还不能确定是负载高还是连接池问题，基本上应该快好了。` | `查询超时是连接池耗尽导致的。已将连接池上限从 10 扩至 50，压测通过。` |
| **第 2 律 `empty-overclaim`** | 禁零信息起手式、无数字虚夸与免责尾巴 | `需要注意的是，本次已彻底解决，相关测试通过，生产表现还需部署后观察。` | `空输入异常已修复，单测 6 条全过。生产环境灰度尚未执行。` |

### 第二层：句法（余光中「中文常态论」与现代汉语竹节流水句）

| 律号与规则 ID | 管什么 | ❌ 西化树状变态 / 温吞说明书腔 | ✅ 汉语竹节常态（短促有力、一眼秒懂） |
| :--- | :--- | :--- | :--- |
| **第 3 律 `bamboo-length`** | 卡死句长（指令≤25 / 汇报≤35 / 说明≤40），禁分号串动作 | `先对配置文件进行备份；同时重启服务从而使配置生效。` | `先备份配置文件。再重启服务。` |
| **第 4 律 `de-stacking`** | 单句「的」≤2 个；以小句做主语，不用「名词的动作」做主语 | `由于接口的调用失败导致了那个在非仓库目录下的配置加载的中断。` | `调用接口失败，导致配置加载中断。`（余光中名例：`横贯公路再度坍方` 而非 `横贯公路的再度坍方`） |
| **第 5 律 `western-shell`** | 剥除 `基于…下 / 在这种…配置下 / 针对…问题` 外壳；风险置顶 | `在这种防抖配置下，每次输入都会重新计时，停止输入后才发送请求。` | `防抖就是连点十次，只认最后一次。停止输入 300 毫秒后才发送请求。` |

### 第三层：字法（中国民机《简化语言规范》与受控核心词典）

完整词表见 [`references/controlled-lexicon.md`](references/controlled-lexicon.md)：

| 律号与规则 ID | 管什么 | ❌ 弱动词 / 黑话伪度词 / 悬空含糊 | ✅ 受控真词（真动词 + 真数字 + 具体点名） |
| :--- | :--- | :--- | :--- |
| **第 6 律 `weak-verb`** | 5 大域 22 个真动词立骨，砍掉「文字的义肢」 | `对日志进行了排查，完成了对空指针的定位并作出修改。` | `我排查了日志，定位到空指针并修改了校验逻辑。` |
| **第 7 律 `buzzword-abstract`** | 禁黑话与余光中痛批的 `具有…性 / 具备…度 / 实现了…化` 伪术语 | `本次最小侵入式收口赋能了查询闭环，具备良好的可用性与扩展性。` | `合并重复查询后，接口耗时从 180ms 降到 45ms，单测 8 条全过。` |
| **第 8 律 `vague-reference`** | 具体点名与准确数字，禁用 `该/其/此/相关/若干` | `对其进行了重试，一部分恢复正常，其余相关测试与记录仍失败。` | `自动重试 12 条被锁任务，成功 9 条，失败 3 条。` |
| **第 9 律 `synonym-rotation`** | 同篇一义一词，禁止近义词轮换 | `先核查配置文件，再检视并检查文件夹权限。` | `先检查配置文件，再检查目录权限。` |

## 三档运行模式（Three Modes）

1. **`report`（汇报档，默认）** —— AI 任务汇报、排障结论、进度说明、PR 总结（**单句 ≤ 35 字**，强制首句死结论 + 已验/未验具体二分）。
2. **`procedure`（指令档）** —— 部署步骤、运维 Runbook、子代理派工 brief（**单句 ≤ 25 字**，风险与条件置顶，一步一动作）。
3. **`descriptive`（说明档）** —— README、架构说明、概念解释（**单句 ≤ 40 字**，直击本质，禁西化套壳）。

## 快速开始

```bash
# 1. 运行内置自检与全量单测（零第三方依赖）
python3 scripts/zh-ste-lint.py --selftest
python3 scripts/zh-ste-jev.py --selftest
python3 -m unittest discover -s tests -v

# 2. 查看「篇法 · 句法 · 字法」三层九律列表
python3 scripts/zh-ste-lint.py --list-rules

# 3. 一条命令跑完「三层九律静态检查 + Jev 篇法语义终审」
python3 scripts/zh-ste-lint.py --mode report --jev examples/after-only.md
```
