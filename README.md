# `zh-ste100-jev-skill` — 中文受控技术与汇报写作技能（`篇法 · 句法 · 字法` 三层九律）

> **不搞拼盘，一层只管一件事：**
> - **第一层【篇法】管“先说什么、后说什么”**（王小波说理章法 + Jev 百毫秒语义终审）
> - **第二层【句法】管“一句话怎么断、怎么顺”**（余光中《论中文的常态与变态》+ 现代汉语竹节流水句）
> - **第三层【字法】管“每个词用哪个、禁哪个”**（中国民机《简化语言规范》+ ASD-STE100 受控词表）
>
> 专治中文 AI 任务报告、排障分析与技术文档**「每个字都认识，串在一起却不知道在说什么，且满篇打太极」**的顽疾。

---

## 核心章法：为什么按「篇法 → 句法 → 字法」三层统合？

英文 **ASD-STE100（简化技术英语）** 解决的是英语的「一词多义」和「右分支从句歧义」；但中文 AI 报告和工程文档的崩坏，同时发生在**谋篇、造句、选词**三个不同层级。把不同来源的规则平铺堆砌会变成大杂烩，因此本项目按中国传统文章学的**「篇法 · 句法 · 字法」**自上而下分层治理：

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 第一层：篇法（谋篇与诚实） ← 王小波议论章法 + Jev（System One）语义终审 │
│   • 第 1 律 taichi-hedge : 结论先行，严禁“基本上/应该已经/大概”打太极   │
│   • 第 2 律 overclaim    : 现象、推测、验证三分，禁套话自夸与满口打包票 │
├─────────────────────────────────────────────────────────────────────────┤
│ 第二层：句法（竹节与语序） ← 余光中《论中文的常态与变态》+ 汉语流水句   │
│   • 第 3 律 bamboo-length: 竹节断句，一事一顿（25/35/40字），禁分号焊长句│
│   • 第 4 律 de-stacking  : 单句“的”≤2 个，以动宾小句做主语而非“X的Y”    │
│   • 第 5 律 western-shell: 剥除“基于…下/针对…问题”欧化壳，风险条件置顶  │
├─────────────────────────────────────────────────────────────────────────┤
│ 第三层：字法（选词与定名） ← 中国民机《简化语言规范》+ ASD-STE100 词表  │
│   • 第 6 律 weak-verb        : 真动词立骨，砍掉“对…进行/作出/完成对…的” │
│   • 第 7 律 buzzword-slang   : 留真术语；上禁黑话伪度词，下禁粗俗俚语   │
│   • 第 8 律 vague-reference  : 点真名与准确数字，禁“该/其/此/相关/若干” │
│   • 第 9 律 synonym-rotation : 同篇一义一词，禁止近义词轮换             │
└─────────────────────────────────────────────────────────────────────────┘
```

## 三层九律详解与正反例对照

### 第一层：篇法（王小波说理章法 —— 清楚、具体、诚实、得体）

管整段话的叙事顺序：**① 先给结论或核心问题 → ② 给原因与证据（解释概念配具体小例子）→ ③ 交代条件与未验证边界 → ④ 给明确下一步**。

| 律号与规则 ID | 管什么 | ❌ 病句（打太极 / 武断 / 满口打包票） | ✅ 受控改写（清楚、具体、诚实） |
| :--- | :--- | :--- | :--- |
| **第 1 律 `taichi-hedge`** | 首句给死判断；未测项明写边界，禁推诿词 | `需要注意的是，鉴权问题基本上应该已经修好了。` | `网关鉴权中间件已修复，单测 6 条全过。浏览器登录尚未联调。` |
| **第 2 律 `overclaim`** | 区分观察现象与推测；禁自夸与绝对化打包票 | `通过优雅的重构已彻底解决，完全没有问题。` | `已修复空输入时的异常，单测通过。生产环境表现待部署后观察。` |

### 第二层：句法（余光中「中文常态论」与现代汉语竹节流水句）

管单句排布。英文修饰语在名词后（右分支），中文修饰语在名词前（左分支）。AI 把条件和动作全塞进「的」字前面，会让读者短期工作记忆挂死。地道中文像竹子一样**一节一节顺着长**，一事一顿：

| 律号与规则 ID | 管什么 | ❌ 西化树状变态句 | ✅ 汉语竹节流水句 |
| :--- | :--- | :--- | :--- |
| **第 3 律 `bamboo-length`** | 卡死句长（指令≤25 / 汇报≤35 / 说明≤40），禁分号串动作 | `先对配置文件进行备份；同时重启服务从而使配置生效。` | `先备份配置文件。再重启服务。` |
| **第 4 律 `de-stacking`** | 单句「的」≤2 个；以小句做主语，不用「名词的动作」做主语 | `由于接口的调用失败导致了那个在非仓库目录下的配置加载的中断。` | `调用接口失败，导致配置加载中断。`（余光中名例：`横贯公路再度坍方` 而非 `横贯公路的再度坍方`） |
| **第 5 律 `western-shell`** | 剥除 `基于…下 / 针对…问题 / 对于…而言` 外壳；风险置顶 | `基于缺少凭证的情况下，针对连接被意外关闭的问题进行了处理。` | `缺少凭证时连接会关闭。我补上了凭证校验，现已恢复。` |

### 第三层：字法（中国民机《简化语言规范》与受控核心词典）

管字词颗粒度（完整词表见 [`references/controlled-lexicon.md`](references/controlled-lexicon.md)）：

| 律号与规则 ID | 管什么 | ❌ 弱动词 / 黑话伪度词 / 粗俗俚语 / 悬空指代 | ✅ 受控真词（真动词 + 准术语 + 真数字） |
| :--- | :--- | :--- | :--- |
| **第 6 律 `weak-verb`** | 5 大域 22 个真动词立骨，砍掉「文字的义肢」 | `对日志进行了排查，完成了对空指针的定位并作出修改。` | `我排查了日志，定位到空指针并修改了校验逻辑。` |
| **第 7 律 `buzzword-slang`** | 留 `幂等/解耦` 真术语；上禁黑话与 `具备…性`，下禁俚语 | `老方案太蠢迟早会炸；新方案赋能闭环，具备良好的可用性。` | `老方案会把所有记录读入内存。新方案改为分批读取，单测全过。` |
| **第 8 律 `vague-reference`** | 具体点名与数字，禁用 `该/其/此/相关/若干` | `对其进行了重试，一部分恢复正常，其余相关记录仍失败。` | `自动重试 12 条被锁任务，成功 9 条，失败 3 条。` |
| **第 9 律 `synonym-rotation`** | 同篇一义一词，禁止近义词轮换 | `先核查配置文件，再检视并检查文件夹权限。` | `先检查配置文件，再检查目录权限。` |

## 三档运行模式（Three Modes）

1. **`report`（汇报档，默认）** —— AI 任务汇报、排障结论、进度说明、代码审查（**单句 ≤ 35 字**，强制首句死结论 + 已验/未验二分）。
2. **`procedure`（指令档）** —— 部署步骤、运维 Runbook、子代理派工 brief（**单句 ≤ 25 字**，风险与条件置顶，一步一动作）。
3. **`descriptive`（说明档）** —— README、架构说明、概念解释、代码注释（**单句 ≤ 40 字**，观点先行 + 具体小例子检验）。

## 快速开始

```bash
# 1. 运行内置自检与全量单测（零第三方依赖）
python3 scripts/zh-ste-lint.py --selftest
python3 scripts/zh-ste-jev.py --selftest
python3 -m unittest discover -s tests -v

# 2. 查看「篇法 · 句法 · 字法」三层九律列表
python3 scripts/zh-ste-lint.py --list-rules

# 3. 一条命令跑完「三层九律静态检查 + Jev 篇法语义终审」
python3 scripts/zh-ste-lint.py --mode report --jev examples/after-only.md
```
