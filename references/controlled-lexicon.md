# 中文受控技术与汇报核心词典（Controlled Chinese Lexicon）

> 对标《民用飞机维修技术数据简化语言规范》附录「允许使用的通用词及维修操作标准句式」与 ASD-STE100 受控词表思想，结合余光中《论中文的常态与变态》去弱动词原则编制。
> 核心纪律：**一义一词、真动词优先、禁用文字义肢、禁用太极含糊词、禁用悬空代词与黑话**。

---

## 二、禁用万能弱动词表（文字的义肢，`nominalization` 硬拦截）

余光中先生在《论中文的常态与变态》中指出，现代汉语受英文名词化（Nominalization）污染，喜欢把一个干脆的动词拆成「弱动词 + 抽象名词」。**本词表中的写法在全部三档中一律作为硬违规拦截**：

| 禁用写法（弱动词 + 名词化） | 必须改写为（真动词直写） |
| --- | --- |
| `对 X 进行分析 / 排查 / 检查 / 修改 / 重构 / 验证 / 同步 / 校验` | `分析 / 排查 / 检查 / 修改 / 重构 / 验证 / 同步 / 校验 X` |
| `完成了对 X 的更新 / 修复 / 部署 / 提炼 / 拆解 / 确认` | `更新 / 修复 / 部署 / 提炼 / 拆解 / 确认了 X` |
| `作出反应 / 作出决定 / 作出调整 / 作出贡献 / 作出判断` | `反应 / 决定 / 调整 / 贡献 / 判断` |
| `加以处理 / 加以限制 / 加以解决 / 加以说明 / 加以保留` | `处理 / 限制 / 解决 / 说明 / 保留` |
| `予以删除 / 予以拒绝 / 予以保留 / 予以支持 / 予以拦截` | `删除 / 拒绝 / 保留 / 支持 / 拦截` |
| `开展调研 / 开展测试 / 开展排查` | `调研 / 测试 / 排查` |
| `做一下处理 / 搞一下优化 / 弄一下配置` | 写出具体动作：`删除空行 / 合并重复查询 / 修改超时配置` |

## 三、禁用太极含糊词表（`taichi-hedge` 与 `vague-quantifier`）

AI 汇报最让人恼火的是用模棱两可的副词掩盖“没查清”或“没验证”。

### 1. 任务汇报档（`report`）硬拦截太极词

| 禁用太极词 | 病态心理 | 受控改写要求 |
| --- | --- | --- |
| `应该已经…` / `理论上…` | 没跑验证就敢报完成 | 先跑验证直接写 `已验证通过`；没跑就直写 `代码已改，尚未运行验证` |
| `基本上…` / `大体上…` / `差不多…` | 藏着尾巴没做完 | 拆开写：`A、B 已完成；C 尚未处理` |
| `似乎…` / `好像…` / `看起来…` | 靠猜不看证据 | 写出观察到的真实报错或日志，再写明确推论 |
| `在一定程度上` / `某种意义上` / `从某种角度来说` | 纯废话垫词，零信息量 | 直接删掉，写出具体影响范围或数字 |
| `需要注意的是` / `值得一提的是` / `显而易见` / `不难看出` | 居高临下的空洞起手式 | 直接删掉；真有风险直接写 `风险：` 或把条件放在动作前 |

### 2. 含糊数量与范围词（全档拦截或预警）

| 禁用含糊词 | 受控改写要求 |
| --- | --- |
| `若干` / `一些` / `几个` / `部分` | 写出准确数字（如 `3 个文件`、`成功 9 条，失败 3 条`） |
| `相关` / `有关` / `相应` / `对应` | 写出具体名字（如把 `修改相关配置` 改为 `修改 .pi/mcp.json`） |
| `适当` / `酌情` / `视情况` / `必要时`（无判定标准时） | 写出触发条件（如把 `适当调小参数` 改为 `若被截断，将 chunk_tokens 调小至 2000`） |

## 四、禁用悬空代词表（`dangling-pronoun`）

中文技术文本里的 `该 / 其 / 此 / 上述` 是造成“不知这句话在指谁”的头号凶手：

| 禁用悬空代词 | 为什么别扭 | 改写准则 |
| --- | --- | --- |
| `该`（`该文件 / 该服务 / 该问题 / 该配置`） | 离前文隔了半句后，读者必须回头找“哪个” | 直接复现短名词（`mcp.json / aoci 服务`）或删掉 `该` |
| `其`（`将其写入 / 当其失败时 / 对其进行`） | 文言残余加英文 `its/it` 直译，极易指代串位 | 点出对象真名，或用竹节句承前省略主语 |
| `此` / `上述` / `前述` | 迫使读者眼球向上回扫，打断阅读流 | 直接写明对象名称或编号 |

## 五、禁用黑话与伪术语表（`jargon-buzzword` 硬拦截）

余光中先生痛批「把简单的话说成貌若高雅的伪术语（如把好看说成可读性颇高）」。以下互联网与 AI 报告黑话一律硬拦截：

| 禁用黑话 / 伪术语 | 必须改写成的人话（具体动作与事实） |
| --- | --- |
| `赋能` / `抓手` / `组合拳` / `生态化反` | 直接写提供什么功能、调用什么工具、解决什么问题 |
| `闭环` / `对齐颗粒度` / `拉齐水位` | 写清「输入→处理→验证通过」或「双方约定字段一致」 |
| `收口` / `兜底` / `收敛边界` | 写清「统一由 X 函数处理」「失败时返回默认值 Y」「限制只读写 Z 目录」 |
| `最小侵入式` / `零侵入` | 写清「只改了 X 文件的 N 行，未动公共接口」 |
| `语义层面` / `心智负担` / `感知度` | 写清「词义与句意」「理解耗时」「用户能否看到提示」 |
| `无缝` / `极致` / `丝滑` / `一站式` / `全方位` / `强大` | 全部删掉，或换成可测量的耗时、步数、命令条数 |

## 六、禁用欧化介词套壳表（`translationese-shell` 软硬拦截）

英文喜欢用介词短语开头（`Under the condition of... / With respect to... / Based on...`），直译成中文就是一副笨重的“拐杖壳”：

| 禁用欧化套壳 | 竹节句脱壳改写法 |
| --- | --- |
| `基于…的情况下` / `在…的基础之上` | 删掉外壳，直接写前提短句：`已有索引时，…` |
| `针对…的问题（进行了…）` | 拆成两节：`X 报 Y 错误。我改了 Z，现已恢复。` |
| `对于…而言` / `就…来说` | 直接把对象做主语：`指令句不超过 25 字。` |
| `通过…的方式来实现…` | 改为顺承动作：`先做 A，再做 B。` 或 `用 A 生成 B。` |
| `由于…的原因所导致的` | 改为：`因为 X，导致 Y。` 或 `Y 是 X 引起的。` |

## 七、同义轮换监控组（`synonym-rotation`）

同一篇文档内若同时出现同一组的 2 个及以上词，Linter 会报警要求全篇统一成 1 个词：

1. **检查组**：`检查` / `核查` / `检视` / `清查`
2. **验证组**：`验证` / `校验` / `核验` / `印证`
3. **修改组**：`修改` / `更改` / `变更` / `改动`
4. **删除组**：`删除` / `移除` / `删掉` / `抹除`
5. **新增组**：`新增` / `添加` / `增设` / `新建`
6. **用户组**：`用户` / `客户` / `使用者` / `终端用户`
7. **文件夹组**：`目录` / `文件夹` / `路径目录`
